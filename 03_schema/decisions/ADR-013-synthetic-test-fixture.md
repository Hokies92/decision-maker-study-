# ADR-013 — The synthetic test record

**Status:** proposed (P3.S01) · **Provenance:** approved by Scott (D3-3, 2026-10-29: "Yes."); design INFERRED (Claude)

## Context
No individual gate choices exist in the source. Without a record that uses the decision-path layer, the layer is never tested.

## Decision
- One file, `03_schema/tests/synthetic_decision_path.xml`, outside `examples/`.
- Root attribute `recordKind="syntheticTest"` (examples use `recordKind="source"`); every fact tagged `SYNTHETIC` (ADR-008).
- Content: one invented decision-maker, no stakeholder attributes, one path that exercises every rule — all five gates, a `0` with reasons pointing to real Q15 items, a later recovery to `1`, one event with `observedAt`, one without.
- Generated by script, like every other instance.
- Excluded from every count, report and analysis. The cross-check fails if a `SYNTHETIC` tag appears outside `tests/`.

## Consequences
- The decision-path layer is proven before real data arrives.
- The file doubles as a template for anyone collecting new data.

## Implementation notes (P3.S02–S05)

Added after the XSD was built and validated against real data. Each note records where the implementation refines the decision above; the decision itself is unchanged.

- The record also carries two synthetic `Answer` elements (Q15_2 selected; Q18 option 4), so the structured-answer slot is validated as well as the decision path.
- `Attributes` (stakeholder nodes per person) is not exercised: the decision above says the invented person carries no stakeholder attributes. The slot is enforced by keyref and checked by the cross-check (no `INFERRED` attributes).
