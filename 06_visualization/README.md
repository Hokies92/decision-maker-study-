# Phase 6 — Visualization (proposed)

Proposal on `gov/phase-6-visualization`. It takes effect only if Scott merges it. Nothing below is built yet.

**Purpose (Scott, 2026-10-29):** "creative ways to visualize the data so that users can experience and see the asymmetry and be able to process it." Concepts come first, and the build follows only after the library exists (D4-3). Both conditions now hold: Phases 4 and 5 have committed outputs.

## First principles

1. **A view answers one question.** If a view can't name its question, it is decoration.
2. **The asymmetry is two-sided.** Every core view shows both sides at once — what customers value against what they get, the vendor's word against the customer's word. A one-sided chart can't show a gap.
3. **Numbers come from files, never from the page.** Each view is generated by a script from committed data and checked against it (GOVERNANCE §5 P6).
4. **The limits travel with the view.**
   - n = 25 rule: cohorts below it are shown but greyed and never compared.
   - The ecological caveat applies to cross-cohort links.
   - Open-ended data links to structured data by concept only.
   - No respondent gets a level or a stakeholder type.

## Candidate views (for the concept sheet — Scott picks)

| # | View | The question it answers | Data (committed) | Form |
|---|---|---|---|---|
| V1 | **The two-sided ledger** | Where do customers get more than they value, and where less? | T04 `value_vs_experience.csv` (9 pairs × 50 usable cohorts) | Paired dots per concept, valued vs received. Gap drawn as a line. Pitch (+0.44) and Case (−0.47) at the two ends |
| V2 | **Gate × cohort explorer** | At which gate does each cohort's experience break down? | T01 `gate_profile.csv`, T03, T09 | Heat grid: five gates × cohorts. Pick a cohort to see its profile against All. Cohorts below n = 25 greyed |
| V3 | **The silent gap** | Which gaps do customers feel but not say? | T04 gaps × `views/coded/t04_link.csv` | Scatter: structured gap (x) against open-ended voice (y). Case sits far out on x and near zero on y |
| V4 | **What wins, what loses** | Which behaviours win accounts and which lose them? | `views/coded/kano.csv`, `cit_behaviours.csv` | Diverging bars: effective (best accounts) right, ineffective (worst) left. Coloured by class: satisfier, dissatisfier, critical |
| V5 | **Two vocabularies** | Where does the vendor have a word and the customer none? | `asymmetry_lexicon.csv`, `views/coded/lexicon_pass2.csv` | Gate-by-gate table: vendor term, customer term, customers' own words from the answers. Gaps shown as empty cells |
| V6 | **Search the customers' words** | What did decision-makers say about a vendor, a role or a behaviour? | `index/answers_search.json`, `codes.csv` | Search and filter page by vendor, person, contact role, code and best / worst. Verbatims shown exactly, by `respid` only |
| V7 | **Thread network** | Which questions move together, and how do they cluster by gate? | T06, T07 outputs, P1 `linkages.csv` | Network diagram: threads as nodes, links as edges, coloured by gate. Statistical links labelled as group-level |
